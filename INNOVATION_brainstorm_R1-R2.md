# Entity Analyzer — инновационный штурм (раунды 1–2)

**Дата:** 25.08.2026
**Формат:** идеационная сессия; ни одна идея не реализована без отдельного цикла проектирования и утверждения
**База:** .NET 10 / WPF MVVM / ноль NuGet-зависимостей в Core · 257 тестов · SMOKE V10 · светлая академическая тема

---

## РАУНД 1 — 28 идей по 8 областям (краткая сводка)

> Полные описания с обоснованиями — в переписке от 25.08.2026; здесь сохранён реестр, чтобы дорожные карты обоих раундов были перед глазами.

### ⚙️ Бэкенд
1. **«Кодекс-скаут»** — discovery непокрытых имён (частотные капитализированные последовательности вне кодекса → кандидаты в карточки). *Средняя / Стратегическая*
2. **Инвертированный индекс корпуса** — `вариант → [(файл, позиция)]` рядом с кэшем; мгновенные пересчёты поверх индекса. *Высокая / Стратегическая*
3. **Дифф-движок прогонов** — позиционный CompareRuns: появления/исчезновения, дельты плотности. *Средняя / Quick Win*
4. **Компиляция паттернов в гибридный автомат** — lexicon-токены всех паттернов в один Ахо–Корасик + пост-фильтрация цепочек. *Средняя / Quick Win*
5. **Потоковый ридер больших файлов** — Channel<T>-конвейер по границам предложений вместо отсечки по размеру. *Средняя / Стратегическая*

### 🖥 Фронтенд
6. **Heat map корпуса** — плиточная карта файлов: размер = объём, насыщенность ветви = плотность. *Средняя / Quick Win*
7. **Command Palette (Ctrl+K)** — единый fuzzy-поиск по всем командам приложения. *Низкая / Quick Win*
8. **Песочница паттернов с live-превью** — вставил предложение → совпадения подчёркнуты на лету. *Низкая / Quick Win*
9. **Diff-вид двух прогонов** — визуализация CompareRuns двумя колонками со стрелками-дельтами. *Средняя / Стратегическая*
10. **Timeline корпуса** — лента файлов по дате/томам с отметками упоминаний. *Средняя / Стратегическая*

### 🏗 Архитектура
11. **Плагинный контракт IAnalysisModule** — формализация жизненного цикла Configure→Scan→Export для всех типов анализа. *Высокая / Стратегическая*
12. **Headless API-хост поверх Core** — минимальный HTTP-слой для удалённого анализа больших корпусов. *Средняя / Стратегическая*
13. **Скриптовые препроцессоры** — ITextPreprocessor + пользовательские C#-скрипты (Roslyn) без пересборки. *Средняя / Quick Win*

### 🔧 DevOps
14. **Performance-gate** — пороговая проверка против baseline.json: >20% замедления = красная сборка. *Низкая / Quick Win*
15. **Self-verifying релиз** — первый запуск новой версии гоняет встроенный мини-корпус со сверкой эталона. *Низкая / Quick Win*
16. **verify.ps1** — вся верификация одной командой: build→test→publish→CLI→смоук→JSON-итог. *Низкая / Quick Win*

### 🎨 UX/UI
17. **Экспорт в экосистемы исследователя** — Obsidian (markdown+[[ссылки]]), Zotero/Excel CSV, Anki-колода. *Низкая / Quick Win*
18. **Режим «вычитки»** — исходник файла в GUI с подчёркиванием находок цветами ветвей, навигация ↑↓. *Средняя / Стратегическая*
19. **Живой статус достоверности** — бейдж уверенности из сигналов fuzzy/порчи/фильтров. *Средняя / Quick Win*

### 🔐 Безопасность
20. **Санитайзер HTML-отчётов** — экранирование + CSP-мета против stored-XSS из корпуса. *Низкая / Quick Win*
21. **Цепочка целостности журнала** — prev_hash в history.jsonl, тампер-евидентная история прогонов. *Низкая / Quick Win*
22. **Приватные кодексы под паролем** — AES + PBKDF2 для коммерческих сеттингов. *Средняя / Стратегическая*

### 🤖 ИИ
23. **LLM-генератор паттернов из примеров** — 3–5 примеров → черновик JSON-паттерна → правка в редакторе. *Средняя / Стратегическая*
24. **Смысловой поиск сверх имён** — офлайн эмбеддинги (ONNX) + свой векторный индекс. *Высокая / Долгосрочная*
25. **Классификатор омонимии** — контекстная модель различает «Наг»-имя/топоним/аббревиатуру. *Высокая / Долгосрочная*

### 💰 Монетизация
26. **Библиотека кодексов и паттернов** — скачиваемые JSON-паки («Мифы Ктулху», «Дюна», «ритуалы», «титулы»). *Низкая / Quick Win*
27. **Pro-ключ для тяжёлых корпусов** — офлайн Ed25519-лицензия снимает лимит корпуса + включает headless API. *Средняя / Стратегическая*
28. **Академические отчёты «под публикацию»** — PDF/DOCX с библиографией, методологией и цепочкой целостности. *Средняя / Стратегическая*

## РАУНД 2 — 30 новых идей (полные описания)

**Правило раунда:** ни одной идеи, пересекающейся с первой партией, — только новое или развитие по новому фронту.
**Срез возможностей:** ядро находит, но не обобщает (нет коллокаций, кластеризации, контрастов); исследование не переносимо (корпус+кодекс+паттерны россыпью в %APPDATA%); знание пользователя не накапливается (вердикты по находкам теряются).

### ⚙️ Ядро и лингвистика

| № | Инновация | Описание и обоснование | Сложность | Приоритет |
|---|-----------|------------------------|-----------|-----------|
| R2-1 | **Шахтёр коллокаций** | Авто-извлечение устойчивых биграмм/триграмм (PMI или лог-правдоподобие, наивный проход по уже токенизированным предложениям) с фильтром капитализации → ранжированные кандидаты в lexicon-словари паттернов. Прямое топливо для «Кодекс-скаута» (R1-1): скаут находит имена, шахтёр — формулы вроде «воющей собаки» рядом с «час». Экспорт кандидата одним кликом прямо в semantic_patterns.json. | Средняя | Стратегическая |
| R2-2 | **Контрастивный анализ корпусов** | Выбор двух корпусов (оригинал vs перевод, автор А vs Б, ранние vs поздние рассказы) → статистика различий по сущностям и паттернам с log-likelihood (стандарт Tools Мэйлорда из digital humanities). Отвечает на исследовательский вопрос «чем мой корпус отличается от эталонного». | Средняя | Стратегическая |
| R2-3 | **Тематическая кластеризация корпуса** | TF-IDF по лемматизированным файлам + k-means без единого NuGet → каждый файл получает тему; плотности сущностей агрегируются по темам («Наг живёт в культистских текстах, Йеб — в морских»). Heat map (R1-6) раскрашивается темами вместо алфавита. | Высокая | Долгосрочная |
| R2-4 | **Анафора-режим** | Опциональный слой: после явного упоминания ближайшие «он/она/оно/Древний» в окне предложений засчитываются как косвенные упоминания с отдельным счётчиком. Честная «плотность присутствия» вместо плотности имён; выключен по умолчанию ради воспроизводимости старых прогонов. | Средняя | Стратегическая |
| R2-5 | **Content-addressable кэш** | Ключ кэша — SHA-256 содержимого (хеш уже считается для дубликатов), а не путь: переименование/перемещение файлов перестаёт инвалидировать кэш. Перестановка половины корпуса = ноль переработки. | Низкая | Quick Win |
| R2-6 | **Watch-режим** | FileSystemWatcher на корпусе + автопрогон изменённых файлов с дебаунсом; новые упоминания всплывают в журнале и тостом. Разовый анализ превращается в дежурный режим растущей библиотеки. | Средняя | Quick Win |

## Ключевые рекомендации

**Раунд 1:** «Кодекс-скаут» (R1-1) — единственная идея, атакующая корневое ограничение «ищу только тех, кого уже знаю»; расширяет само знание пользователя о корпусе поверх существующей инфраструктуры; MVP за пару дней.

**Раунд 2:** связка **«.eaproj» (R2-11) + «Хранилище вердиктов» (R2-13)** — фундамент минимум шести идей обеих партий (R1-12, R1-21, R2-6, R2-12, R2-24, R2-26, R2-28). Сегодня исследование существует только как состояние %APPDATA% конкретной машины: один сбой диска стирает месяцы работы над кодексом, перенос требует ручного копирования четырёх файлов по памяти. Вердикты превращают единственный невозобновляемый ресурс — экспертные решения пользователя о каждом совпадении — в накапливаемый актив. Ни одна из этих вещей не даёт красивого скриншота, но именно они отличают «утилиту» от «рабочего инструмента исследования».
