## [Unreleased]

### Added
- Review results are now exported. When a session has at least one verdict,
  `ExportAll` additionally writes `review_report.md` (summary: total/reviewed/
  confirmed/rejected/uncertain, files with unreviewed mentions, plus a decisions
  table) and `review_report.csv` (machine-readable; RFC 4180 quoting; stable
  `confirmed/rejected/uncertain` codes matching `verdicts.jsonl`). Without
  verdicts the protocol is not written at all, so the regular report set and
  their content stay byte-identical. The Export page shows the current review
  progress and whether the protocol will be written. Headless runs opt in with
  `--review-report`: the CLI applies saved verdicts using SHA-256 from the
  incremental index (falling back to reading only unindexed files) and then
  writes the same protocol.
- The results page can jump to the next file with unreviewed mentions and
  shows corpus-wide review progress. Navigation respects the current file
  filters first; if they contain no work, it resets them and continues across
  the whole corpus, switching the verdict filter to «Непроверенные».
- Added a committed synthetic smoke-corpus pipeline anchor, independent of the
  real corpus: 16 documented edge-case files, 14 analyzed, 13 mentions in 12
  files, and a pinned canonical `entities_table.csv` SHA-256
  `E50A1559695D13CED7708C640CDD4A73E5C42C3C1EEBF568B1933196AE71B34C`.
  The fixture explicitly covers `ё`/`е` as well as case and Latin diacritics.
  A frozen three-entity `catalog.json` adds `Толстой` and `Пушкин` to the
  existing `Наг и Йеб` card, so `16-multi-entity-context.txt` exercises two
  distinct entities in one sentence. The pre-fix CLI produces 12 mentions
  there (Pushkin is lost); the fixed CLI produces 13. The catalog SHA-256 is
  `15C4DA523724011167CC9E470A5E549D0D5A99E192258A85B49DA5A3FF34D5F7`.
  The old anchor `A81A1086...` is historical: it could not detect context-only
  deduplication because no smoke file had two distinct catalog entities in one
  context. `verify.ps1` and the Windows/Linux CI matrix run the fixture twice
  and compare the hashes; `scripts/update-smoke-baseline.ps1 -Reason` is the
  only supported re-baseline path and refuses a dirty working tree.
- Added committed ONNX golden fixtures for the optional E5 int8 profile:
  `test-fixtures/onnx-golden/golden_int8.json` contains 12 ru/en/mixed
  query/document vectors generated by an explicit Python `onnxruntime`
  pipeline from the same `model_int8.onnx` (prefixes, BOS/EOS, truncation with
  EOS reserve, masked mean including specials, L2). C# tests compare token IDs
  exactly and vectors with cosine > 0.9999 on Windows / >= 0.99 on
  Linux/macOS: one Ubuntu runner measured `0.996705` for `ru-query` due to
  different int8 kernels, while the next runner passed the strict floor, so
  the portable floor is documented rather than hidden. A separate
  `reference_fp32.json` records the sentence-transformers fp32 reference; the
  measured int8-vs-fp32 minimum is `0.979531` (mean `0.985313`), so the
  documented loose floor is `0.975`, not 0.99. A separate
  `onnx-golden-tests` CI job keeps numerical failures out of the fast
  `onnx-model-tests` job; it runs on Ubuntu x64 and macOS 14 ARM64. The
  Linux/macOS `0.99` floor detects catastrophes, not regressions; the strict
  `0.9999` correctness check remains Windows-only until kernel parity. The
  generator refuses non-pinned Python/ONNX Runtime versions, and the documented
  ORT-bump policy is regenerate-both-fixtures-and-re-baseline, never just raise
  a tolerance. Model weights remain uncommitted.
- Added two end-to-end retrieval tests through `VectorIndex` and the real int8
  E5 embedder, in the separate `onnx-retrieval-tests` job. The first asserts
  that «Лев Толстой написал роман „Война и мир“» ranks above the Pushkin
  document for the matching title query; the second uses the title-free
  paraphrase «произведение о войне 1812 года» and gets the same ranking. The
  layer is named retrieval, not semantic understanding, and is documented as
  topical retrieval rather than homonym disambiguation. The bare query `Наг`
  ranks the dog-breed document (`0.906874`) above the ancient-priest document
  (`0.895978`), so `HomonymClassifier`, not E5-small, is the disambiguation
  mechanism. A longer paraphrase is honestly recorded as a ceiling: it is
  effectively tied and flips by `0.0003` (`pushkin=0.824651`,
  `tolstoy=0.824333`), so it is not used as a passing test.
- The fp32-reference assertion now states that a floor failure is a
  model-quality result, not a C# correctness bug: the resolution is to
  re-evaluate int8 against fp16/fp32 or regenerate the reference, never to
  loosen the C# pipeline check.
- Documented the Phase C retrieval contract before implementation:
  `semantic_neighbors.csv` uses one row per `(query, rank)`, top-N 5-10, and
  carries `score_bow` and `score_onnx` on the same pairs. The go/no-go metric is
  cross-lingual entity matching, where BoW has zero lexical overlap; the
  labeled-set and top-10 stability checks are secondary. Stability zones are
  fixed before code: `<30%` top-10 overlap means the methods return
  fundamentally different neighborhoods and a labeled set must decide which is
  better; `30-70%` means ONNX complements BoW and cross-lingual matching is the
  decisive argument; `>70%` means ONNX adds little on this corpus and Phase C
  should be reconsidered or limited to the cross-lingual scenario. The file is
  explicitly exploratory, not an anchor, until a signal is established.
- Strengthened the E5 retrieval boundary: long descriptive paraphrases without
  canonical names are a **binary failure mode**, not a hard case; the
  `0.000318` tie is two orders below int8 cross-kernel noise (~`0.003`). The
  documented fix is query representation (entity-name extraction before
  embedding), not a larger model tier.
- Recorded the golden platform buckets (`Windows-x64: 0.9999`; `Linux-x64`,
  `macOS-arm64: 0.99`) and required a fresh cross-platform int8 measurement
  before adding a new runner. Documented the model repository as a single point
  of failure: SHA-256 detects substitution but does not make recovery automatic,
  and no `fallback_url` is configured.
- Saved verdicts are restored for every mention when a session loads, using
  SHA-256 from the incremental index when available, so the corpus counter and
  the next-file action start from the same state as the per-file list.

### Fixed
- Re-baselined the full-corpus anchor after the deduplication fix.
  `entities_table.csv` SHA-256 changed from
  `06A3DE3BC9E84881F58CD8D567F736DE1888F5EC48F8D60AB8CDE3CC532C95D0` to
  `690644D690C8B4FDCB44D699B4BA7F904FEB8DD6D10473F4C9632D29EAAB8EEE` on the
  same 10,531-file corpus; the Merkle root and file counts are unchanged, so
  this is a pipeline change, not corpus drift. The controlled probe showed one
  row before the fix and two rows after (`Толстой` and `Пушкин` in one context).
  Both old snapshots are marked `superseded_by: dedup_fix_2026-10-24` and are
  reproducible only with the old published CLI. On the 37,406-row multi-entity
  diagnostic, grouping by `(entity, context)` gives `max count = 1` and zero
  duplicate groups, so the extra 1,394 mentions are restored, not doubled.
- Context-window deduplication no longer drops distinct entities that share a
  sentence or context window. The key is now `(entity, context)` both within a
  file and across files; the same entity in the same context is still collapsed,
  but distinct entities in one context (for example, `Толстой и Пушкин` and
  `Москва и Санкт-Петербург`) produce one mention per entity. Comma-separated
  name lists can still be rejected by the separate listing filter. On a
  full-corpus diagnostic with a 37-card codex and the `minimal` preset, the old
  key produced 36,012 mentions;
  the fixed key produces 37,406, preserving 1,394 mentions across 1,260
  multi-entity contexts. The smoke `Наг и Йеб` result is a single canonical
  pair card, not evidence of a conjunction merge. Added unit and engine
  regression tests for within-file and cross-file deduplication.
- The GUI smoke brings the main window to the foreground and retries palette
  focus before asserting focus restoration. A background verification run could
  otherwise fail or hang when another window owned focus, even though the
  application itself was healthy.
- The legacy-config integration test no longer embeds a developer-specific
  absolute path: it searches upward from the test output directory for
  `config.yaml` and skips cleanly in the app-only CI layout. The legacy
  `run_tests.ps1` and `test_install.py` now use their own directory instead of
  a hardcoded desktop path.
- The Export tab's review hint now refreshes immediately after a single
  verdict, a bulk verdict, or an undo. It could previously still say
  «0 проверено» until the next analysis even though the verdict was saved.
- Bulk verdicts are now undone as one action: `Ctrl+Z` restores the whole
  selection instead of only the last card. Batch storage uses a single
  `VerdictStore.RemoveRange` rewrite.
- Duplicate content is counted before the cache fast path. A warm cache could
  previously return cached results for a duplicate and bypass
  `SkippedDuplicate`; a regression test covers the cold/warm pair.
- Recent-project settings are pruned from missing or invalid paths at startup
  and after removal; invalid legacy entries can no longer break project opening.
- The command palette no longer drops long codex cards. Their `SearchText`
  contains hundreds of aliases, and the length penalty in `FuzzyFilter.Score`
  made the context score negative; a title match is now considered even when
  the full context does not score.

### Changed
- The homonym classifier now scores a local context window instead of using
  the first personal word anywhere in the sentence: inflected forms of the
  term (`Нага`, `Наге`, `Нагом`) are matched, place prepositions work through
  a place phrase (`в древний город Наг`), place nouns count, and dotted
  acronyms are recognized. Explicit personal or place context can refine an
  all-caps term, while a neutral CAPS form stays an abbreviation. The public
  `Classify` contract is unchanged.
- VectorIndex and its offline BagOfWords embedder are hardened as the
  dependency-free Phase A: process-stable FNV-1a buckets replace randomized
  `string.GetHashCode()`, tokenization ignores case and surrounding punctuation,
  repeated ids replace rather than duplicate, dimensions and finite values are
  validated, empty or punctuation-only queries return no results, and ties sort
  by ordinal id. BoW remains the deterministic default; ONNX is not added and
  stays a separate opt-in step.
- The ONNX Phase B contract is prepared without runtime or model files:
  `IRoleAwareEmbedder` distinguishes `Document` and `Query`, so the mandatory
  E5 `passage:`/`query:` prefixes are enforced by `VectorIndex` instead of
  being left to callers. The selected E5 profile is 384-dimensional with
  L2-normalized non-empty vectors and a zero vector for empty input; a
  dependency-free stub covers dimensions, normalization, role dispatch, and
  empty queries. E5 uses XLM-R SentencePiece rather than BERT/`vocab.txt`.
  BoW remains default; `Microsoft.ML.OnnxRuntime` and model files are not
  added. Core suite is now 862 tests.
- ONNX Phase B step 3 adds the separate `EntityAnalyzer.Embedders.Onnx`
  project without touching the analysis pipeline: `Microsoft.ML.OnnxRuntime`
  1.31.0 and stable `Microsoft.ML.Tokenizers` 2.0.1 implement
  `OnnxE5Embedder` / `OnnxE5Options`. SentencePiece IDs are remapped to the
  XLM-R fairseq layout (`+1` for regular tokens; `<s>`/`<pad>`/`</s>`/`<unk>`
  become 0/1/2/3), BOS/EOS are emitted explicitly, and truncation preserves
  EOS. The Xenova model requires `input_ids`, `attention_mask`, and
  `token_type_ids` (int64); the output is [1, tokens, 384]. Pooling is masked
  mean over `last_hidden_state` followed by L2 normalization, with a zero
  vector for an empty mask. Missing files point to `scripts/fetch-model.ps1`;
  there is no runtime download. BoW remains the default and
  `entities_table.csv` is unaffected. The new suite has 15 tests (3 skipped
  without weights): contract, masked pooling, role prefixes, truncation,
  tokenizer ID tests, missing-model diagnostics, and a model-gated ONNX
  session smoke test.
  CI adds an `onnx-model-tests` job keyed by the `models/manifest.json` hash;
  contributor PRs without a cached model skip cleanly, while a main push may
  seed the cache through the explicit fetch script and verifies it with
  `-Verify` first. Core remains 862 tests; total is 877.
- `verify.ps1` now sums the final summary line of every test project instead of
  taking the first match. Without this, the new ONNX project would make the
  baseline see 15 tests and fail the `>=257` guard while 862 Core tests were
  hidden later in the log.
- ONNX Phase B model-fetch infrastructure is added without packages or
  committed weights: `dotnet/scripts/fetch-model.ps1` and `fetch-model.sh` pin
  `Xenova/multilingual-e5-small` at revision `3acb1fa4`, verify sizes and
  SHA-256 before atomically renaming `.part` files, and update
  `dotnet/models/manifest.json` plus `dotnet/models/README.md` in `-RecordHashes`;
  `-Verify` is offline and strict, and `-Force` re-downloads. The
  `model_int8.onnx` hash is pinned to
  `4d24e2bc01a447951524466ef533e52944bf48509e6552810bcee1a2711cb02c`;
  tokenizer, config, and SentencePiece hashes were recorded from the
  controlled first download. `models/` weights are ignored and no ONNX or
  tokenizer package was added.
- Repository hygiene: local-only artifacts (`TestResults/*.trx` with machine
  paths, top-level `output/` and `publish/output` with corpus reports,
  `cli_pid.txt`, PDBs, `.earepro`, `.mcp.json`, `.tessera`, `output_dotnet`,
  `reports`) are no longer tracked; they remain on disk and are ignored. A
  sanitized orphan snapshot is published as
  [`sanitized/v18.1`](https://github.com/DEICIDEGRAUER/entity_analyzer/tree/sanitized/v18.1):
  source and docs only, 407 files, without prebuilt publish binaries; the
  app-only `main` branch keeps its own layout.
- Review and quote-book toolbars use `WrapPanel`, so controls wrap instead of
  being clipped on narrow windows.
- Command-palette ranking moved from the WPF window to
  `Core/Text/PaletteRanker`; title matches still outrank context-only matches,
  and the 200-result limit/duplicate handling are unchanged.
- The rail now has a visible “Поиск и команды” button with a UIA name, so the
  palette is discoverable without knowing `Ctrl+K`.
- The command palette now shows a localized empty state and a live result
  count, labels its search field and result list for UIA, and restores keyboard
  focus after closing without executing a command.
- The palette footer has an explicit «Выполнить» button with a UIA name for
  mouse, touch, and screen-reader users; Enter remains the keyboard shortcut.
- The command palette remembers the eight most recent commands in
  `settings.json` and shows them first when the query is empty. Keys are stable
  for pages, codex cards, quotes, reports, files, and mentions.
- The results filter can now select unreviewed, confirmed, rejected, or
  uncertain mentions by verdict; a changed verdict immediately removes rows
  that no longer match the active filter. Bulk verdict actions and undo rebuild
  the visible selection in every verdict mode, and the review progress text is
  a polite live region. The filter toolbar wraps on narrow windows.
- The CI culture matrix now forces English dotnet CLI output, reports exact
  passed/failed/total counts for every culture, restores its environment in a
  `finally` block, and prints a summary table.
- File hashes used by verdicts and stars are taken from the incremental index
  before falling back to reading the file; the hash cache is cleared for every
  new session.
- README updated to the current 862-test baseline.
- Remote CI now runs the Core/CLI suite on Windows and Linux in ru-RU,
  en-US, and tr-TR, builds WPF only on Windows, uses an isolated profile,
  and publishes failure diagnostics. The path-restamping test is
  platform-neutral, and the microbenchmark compares the median of three
  runs with a 50% guard instead of a single 15% comparison.
