# Entity Analyzer Desktop

Десктопное приложение **Windows 11** (.NET 10 / WPF) для поиска упоминаний сущностей
(лавкрафтианского пантеона и любых других) в больших корпусах текстовых файлов.
Полный перенос и развитие движка из Python-версии проекта `entity_analyzer`.

---

## Быстрый старт

| Что | Где |
|---|---|
| Ярлык на рабочем столе | **«Entity Analyzer»** (создан скриптом, запускает publish-сборку) |
| GUI-приложение | `publish\EntityAnalyzer.exe` |
| Консольный компаньон | `publish-cli\EntityAnalyzer.Cli.exe` |
| Тесты | `dotnet test tests\EntityAnalyzer.Core.Tests` |

**Кодекс мира встроен в приложение** (карточка «Наг и Йеб», 562 алиаса, 8 категорий,
8 типов связей) — импорт не нужен. Правки автосохраняются в `%APPDATA%\EntityAnalyzer\codex.json`
(легаси `user_catalog.json` мигрируется автоматически при первом запуске).

## Кодекс: карточки, категории, связи

Страница **«✦ Кодекс»** — энциклопедия мира:

- **Универсальные карточки** любых категорий: Божество, Артефакт, Локация, Раса/Народ,
  Культ, Событие, Персонаж, Произведение + **свои категории** (страница «▦ Схемы»).
- **Конструктор схем**: для каждой категории — свой набор типизированных полей
  (текст, многострочный, число, дата, флаг, выбор из словаря, ссылка на карточку, список),
  порядок полей меняется стрелками; поля можно добавлять и конкретной карточке.
- **Типизированные связи** («владеет», «находится в», «служит»…) с автоматическими
  обратными строками; словарь связей редактируется.
- **Галерея/таблица**, поиск по всем полям, фильтры по категории/группе/тегу/цвету/
  наличию упоминаний, сортировка по числу упоминаний из корпуса.
- **Объединение дубликатов** (алиасы, связи и поля переносятся), **путь между карточками**
  (BFS до 4 шагов), **предложения связей** из ко-упоминаний после анализа.
- Вкладка «Упоминания» — цитаты из последнего анализа с переходом в полный текст.
- Экспорт/импорт: **Markdown-заметки** (Obsidian-совместимые, [[вики-ссылки]] + front-matter),
  полный **JSON**, массовый **CSV**-импорт, интерактивный **HTML-атлас мира** (галерея + граф).

## Архитектура

```
EntityAnalyzer.slnx
├── src/
│   ├── EntityAnalyzer.Core      — движок (net10.0, без UI-зависимостей)
│   │   ├── Matching/            — автомат Ахо–Корасика (свой, pyahocorasick-совместимый)
│   │   ├── Variants/            — фабрика вариантов: транслитерация → дефисы → склонения → порча
│   │   ├── Genealogy/           — GEDCOM, читаемый текст, семейное древо и его HTML
│   │   ├── Chronology/          — автосборка хронологии мира (годы, давность, эры)
│   │   ├── Geography/           — классы мест, газеттир, карта Leaflet, Nominatim
│   │   ├── Hierarchy/           — древо иерархии из типизированных связей
│   │   ├── Text/                — нормализация, сплиттер предложений, построитель контекста
│   │   ├── Filtering/           — границы слов, ломаные слова, перечни, титулы, общеупотребительные
│   │   ├── Fuzzy/               — Левенштейн по окнам слов для пропущенных сущностей
│   │   ├── Themes/              — тематическая классификация контекстов (ключевые слова)
│   │   ├── Analysis/            — параллельный движок, модели, метрики-воронка
│   │   ├── Persistence/         — JSON-кэш (SHA-256 контента), экспорт TXT/JSON/CSV/HTML
│   │   └── Configuration/       — опции, пресеты, импортёр легаси config.yaml
│   ├── EntityAnalyzer.App       — WPF GUI (MVVM, темы «Академическая» и «Северный ветер»)
│   ├── EntityAnalyzer.Cli       — headless-прогоны для планировщика/CI
│   └── EntityAnalyzer.Embedders.Onnx — опциональный E5/ONNX (opt-in, не в пайплайне)
├── models/                      — README и manifest.json; веса моделей игнорируются
├── scripts/                     — fetch-model.ps1 / fetch-model.sh (явная загрузка)
├── test-fixtures/onnx-golden/   — golden int8/fp32 JSON и генератор (весов нет)
└── tests/
    ├── EntityAnalyzer.Core.Tests — xUnit, 862 теста (TDD)
    └── EntityAnalyzer.Embedders.Onnx.Tests — xUnit, 20 тестов (6 model-gated)
```

Правило зависимостей: App/Cli → Core; Embedders.Onnx → Core. Core не знает
об ONNX, а основной пайплайн не ссылается на Embedders.Onnx.
Ядро полностью покрыто тестами (автомат, текст, фильтры, варианты, движок, кэш, экспортёр, импортёр).

## Улучшения относительно Python-версии

1. **Переносимость** — никаких захардкоженных путей `/storage/emulated/0`; всё настраивается и запоминается.
2. **GUI вместо консольного меню**: живой прогресс, отмена, журнал, интерактивный просмотр результатов с подсветкой упоминаний.
3. **Корректные координаты**: предложения хранят позиции в исходном тексте → точные номера строк (в оригинале переносы схлопывались и номера плыли).
4. **Не режем полезное**: короткие предложения сохраняются (Python их молча терял); десятичные числа `3.14` не рвутся; диалоговое тире не разрезает реплику («Стой! — сказал он»).
5. **Юникод-границы слов** + цифры; детерминированная генерация вариантов (в Python порядок множеств зависел от hash-seed).
6. **Надёжный кэш**: SHA-256 по содержимому файла + подпись настроек; атомарные записи; битый индекс деградирует в пустой; пакетный сброс индекса.
7. **Экспорт**: TXT + JSON + CSV + HTML (с подсветкой) + папки по сущностям/темам + индекс вариантов; при наличии вердиктов — протокол проверки `review_report.md` + `review_report.csv` (аддитивно, обычный набор отчётов не меняется); кнопка копирования цитаты в буфер.
8. **Метрики-воронка** прямо в интерфейсе: raw → границы → перечни/титулы → итог.
9. **Тематическая классификация** контекстов без SBERT — офлайн, ключевыми словами.
10. **Fuzzy-поиск** переписан на индекс длин + ограниченный Левенштейн: тот же охват на порядки быстрее (корпус ~8.7k файлов ≈ 40 c).
11. **238 юнит-теста**, включая интеграционные прогоны движка (UTF-8/UTF-16/CP1251, дубликаты, семантические паттерны, совместные упоминания).
12. **Редактор сущностей** по схеме «черновик → Применить»: поля формы привязаны к строкам VM, а не к immutable-записи; кнопка активна при несохранённых правках и валидном имени.
13. **Встроенный каталог**: `Core/Resources/default_catalog.json` (генерируется инструментом `tools/ConfigConverter`), работает из коробки; пользовательский слой — `user_catalog.json` в AppData.
14. **ReadinessEvaluator**: чистая логика готовности запуска с человекочитаемыми причинами блокировки (подсказка у кнопки + tooltip).
15. **Синхронная навигация**: программные переходы (автопереход к результатам) подсвечивают нужный пункт рейки — биндинги Nav* вместо code-behind.
16. **Миграция легаси-путей**: андроидные пути (`/storage/emulated/…`) из старых настроек вычищаются при загрузке; YAML-импорт принимает путь корпуса только если он реально существует.
13. **Иконка приложения** (`Assets\app.ico`, «око Нага») — в exe, в заголовке окна и в ярлыке.
14. **UI-смоук-регрессия** `ui_smoke.ps1`: полный цикл — каталог, тумблер сущности, тема, анализ, вердикт, подсказка и реальная выгрузка `review_report.md/.csv` (с проверкой отсутствия протокола без вердиктов).
15. **Включение/отключение сущностей**: чекбокс в списке — отключённая остаётся в редакторе, но исключается из поиска (автопересборка).
16. **Анти-мусорные фильтры** (все переключаемые на «Обзоре»): структурный детектор перечислений (запятые/буллеты/Title-Case цепочки), чёрный список заголовков («Великие ужасы и тайны…», оглавления), осмысленность (доля служебных слов), межфайловая дедупликация контекстов (×N вместо повторов). На реальном корпусе: 822 → 403 упоминания, мусорные справочники отсечены. Примечание (QA N12): тяжёлые пресеты строят более широкие контексты — соседние цитаты чаще схлопываются дедупом, поэтому уникальных цитат может быть меньше, чем в лёгких профилях; совпадения при этом учтены полностью.
17. **Скорость**: отложенное параллельное чтение файлов, индекс строк (бинарный поиск вместо O(n) на упоминание), сплиттер без материализации строк предложений. Холодный прогон 8730 файлов: 13.8 c → 7.9 c.
18. **Генератор тем**: палитра выводится из тона + режима; 7 пресетов + свой тон слайдером; применение на лету через DynamicResource overlay.
19. **Страница «Отчёты»**: дерево выходного каталога (по сущностям), встроенный просмотр txt/json/csv и html-отчётов; отчёты пишутся автоматически после каждого анализа.
20. **Пользовательские regex-исключения**: многострочное поле на «Обзоре»; невалидные паттерны пропускаются с записью в лог.
21. **Морфология русских форм**: падежи + множественное число генерируются автоматически (Наг → Нага/Нагу/Нагом…, Шуб-Ниггурат → Шуб-Ниггурата).
22. **Форматы корпуса**: txt, md, html/xhtml, epub (spine-порядок), docx, pdf (best-effort извлечение текстовых операторов).
23. **Граф связей** (cooccurrence_graph.html — интерактивный canvas) и **облако вариантов** (variant_cloud.html + variants_frequency.txt).
24. **Инкрементальный режим**: неизменённые файлы не читаются с диска (индекс path→hash по размеру+mtime); повторный прогон 8730 файлов ≈ 6–7 c вместо 14–17 c.
25. **Drill-down**: кнопка «📖 Полный текст» открывает исходный файл с подсветкой всех совпадений.
26. **Виртуальные корпуса**: список дополнительных папок на «Обзоре» (+ CLI --extra-dir).
27. **Фильтр результатов**: поиск + режимы Все / Точные / Fuzzy.
28. **ETA и скорость** в прогрессе (файл/с, оценка остатка).
29. **Масштаб интерфейса**: Ctrl+колесо мыши (0.8×–1.6×), сохраняется.
30. **Markdown-отчёт** (entities_report.md) и максимально подробный analysis_report.txt: конфигурация, корпус, кодировки, полная воронка, тайминги стадий, группы, темы, топ вариантов, повторы, ошибки.
31. **История прогонов** (append-only JSONL): страница «⏳ История» со списком, деталями и сравнением с последним прогоном.
32. **Журнал изменений каталога** (%APPDATA%\EntityAnalyzer\catalog_history.jsonl), кнопка «📜 Журнал» на странице сущностей.
33. **Структурированный лог** %APPDATA%\EntityAnalyzer\logs\app-*.log (ротация 14 дней) + перехват необработанных исключений UI.
34. **Группы сущностей**: поле «Группа» в редакторе, массовое включение/отключение группы, статистика по группам в отчётах.
35. **Bench-набор** tools/Bench: median-of-N замеры ядра (транслитерация, декодирование, нормализация, сплиттер, автомат, фильтры, полный прогон) + baseline.json.
36. **Форматы корпуса**: txt, md, html, rtf, fb2, epub, docx, odt, pdf (best-effort), doc (best-effort), mobi/prc/azw (PalmDOC), azw3 (KF8/HUFF — не поддерживается), cbz (ComicInfo), cbr/djvu/lit — с предупреждениями. Список настраивается на «Обзоре» → «Форматы файлов».
37. **Семантические паттерны v2**: токен `capitalized`, повторы `min`/`max` на токене, встроенный паттерн «Названия периодов» («Год Красной Луны», «Час Воющей Собаки», «Эры Великой Расы»). Редактор паттернов и обособленный скан — вкладка «Поиск и паттерны» на «Обзоре»; находки сохраняются в `by_pattern/<id>/matches.txt|csv|json`. CLI: `--patterns-only`.
38. **Справка**: страница обучения (быстрый старт, туториал по конфигурации паттернов с примерами JSON, форматы, горячие клавиши, FAQ).
39. **Регулируемые панели**: GridSplitter'ы между колонками Обзора/Результатов/Кодекса/Отчётов; навигационная рейка сворачивается кнопкой ‹ / › (состояние сохраняется).
40. **Навигация**: Обзор, Результаты, Кодекс, Схемы, Отчёты, История, «Поиск и паттерны» (кнопка → вкладка на «Обзоре»), Справка. Горячие клавиши: Ctrl+F — поиск страницы, F5 — обновить отчёты/историю.
41. **Профили поиска** в GUI подписаны по-русски («Быстрый (light)», «Расширенный (extended)…»); id совместимы с settings.json и CLI.
42. **Вердикты пользователя** (R2-13): кнопки «✓ подтверждено / ✗ ложное / ? спорно» на карточке цитаты пишут в `%APPDATA%\EntityAnalyzer\verdicts.jsonl` (append-only JSONL, ключ = хеш файла + офсет + вариант). Фильтр «ПОКАЗ» показывает непроверенные, подтверждённые, ложные или спорные цитаты; прогресс проверки озвучивается как live-region. Накопленная разметка отсекает шум и готовит выборку для будущих классификаторов.
43. **Исследование как файл .eaproj** (R2-11): ZIP-пакет с манифестом, кодексом, паттернами и настройками — перенос исследования одним файлом; формат читается любым архиватором (`Core/Persistence/ProjectPackage.cs`).
44. **Экспорт в экосистемы исследователя** (R1-17): Obsidian-Markdown уже был; добавлены Anki-колода (TSV с управляющими заголовками) и Zotero/Excel-CSV с BOM, симметричный штатному импортёру.
45. **CSP-санитайзер HTML-отчётов** (R1-20): все self-contained отчёты (entities_report, граф, облако, атлас) объявляют Content-Security-Policy; экранирование покрывает кавычки; разметка из корпуса никогда не становится разметкой.
46. **Content-addressable кэш** (R2-5): ключ кэша результатов — SHA-256 контента («хеш|подпись»); переименование/перемещение файлов не приводит к реанализу. BUG-012: символ `|` в имени файла кэша молча ломал запись на Windows — имя файла теперь SHA-256-отпечаток ключа; идентификация файла (имя/путь) штампуется поверх кэшированного результата.
47. **Фаззинг парсеров** (R2-15): контракт «никогда не исключение» для всех экстракторов форматов закреплён property-тестами (случайные байты, магия+мусор, обрезанные реальные файлы).
48. **Демо-корпус за 30 секунд** (R2-18): кнопка на «Обзоре» записывает встроенный микрокорпус (5 текстов) и сразу запускает анализ — полный цикл без выбора папок.
49. **Изоляция кликом** (R2-21): клик по имени файла в результатах = фильтр «только этот файл»; хлебная крошка снимает фильтр.
50. **Performance-gate** (R1-14): `tools/Bench --gate [--threshold 1.5]` — сравнение 7 стадий с эталоном (`bench/baseline.json`, порог ×1.5); шаг `bench-gate` встроен в `verify.ps1` между CLI-проверкой и смоуком. Синтетический pipeline anchor — `test-fixtures/smoke-corpus/` (15 файлов, 11 упоминаний, canonical `A81A1086...`); `verify.ps1` и CI прогоняют его дважды и сверяют хеш.
51. **verify.ps1** (R1-16): вся верификация одной командой — build → test → publish → CLI на изолированном корпусе → JSON-итог `_scratch/verify_result.json`; `-WithGuiSmoke` добавляет GUI-смоук.
52. **Цепочка целостности журнала** (R1-21): каждая запись history.jsonl несёт prev_hash + SHA-256 содержимого; `JournalIntegrity.Verify` обнаруживает тихую правку/удаление записей. Легаси-записи без хешей легальны.
53. **«Кодекс-скаут»** (R1-1): частотные капитализированные последовательности вне кодекса → кандидаты в карточки (`Core/Discovery/CodexScout.cs`). 57. **Событийная шина** (R2-14): `Core/Events/EventBus.cs` — потокобезопасный pub/sub с изоляцией исключений подписчиков; движок публикует `AnalysisCompletedEvent`, watch-режим и будущие потребители подписываются.

## Замечания

- Легаси пути кэша вида `/storage/emulated/0/…` автоматически перенаправляются в `<out>\.cache`.
- Кириллические пути в аргументах CLI могут искажаться консолью — используйте ASCII-путь или джанкшен (`corpus` уже создан на `ТЕКСТЫ`).
- Коды возврата CLI: 0 — успех; 2 — ошибка аргументов/путей/каталога (в т.ч. повреждённый --catalog, неизвестные форматы без валидных). Необработанных крашей нет.
- Кодировки: UTF-8 (строгая), CP1251 (легаси), UTF-16 LE/BE по BOM. Выходная папка и кэш автоматически исключаются из сканирования корпуса.
- Воронка в отчётах разделяет отклонения фильтров, схлопнутые перекрытия вариантов (OverlapsResolved) и скрытые лимитом цитат (DisplayCapped); строка «Сверка воронки» гарантирует, что арифметика сходится до нуля. Тихие пропуски файлов сводятся в строку «Пропущено: N больших, M пустых, K дубликатов». Интеграционный тест в постоянном наборе: `HeadlessServerIntegrationTests` — реальный HttpListener на свободном порту: health/analyze/400/404 и graceful shutdown по CancellationToken.

123. **Группа 3: тематические отрывки и словари** (R3-1, item 52): `Core/Themes` — пять встроенных словарей («География», «Архитектура», «Культ», «Битвы», «Пророчества») плюс свои темы и слова из `%APPDATA%\EntityAnalyzer\user_themes.json`; матчер понимает падежные формы, средний род («моря», «морями», «копьях») и длинные основы («география» → «географический»), короткие основы по префиксу не матчатся («море» не ловит «мораль»). «Сборщик отрывков» на «Обзоре»: выбор темы и сущности, отрывки берутся из готовой сессии анализа (корпус не пересканируется), свои слова добавляются в словарь тут же и сохраняются, экспорт MD/CSV/JSON с файлом и позицией, список отрывков с точечной подсветкой слов темы и открытием файла. На «Результатах» — совместный фильтр «Тема» + «Сущность» по файлам и цитатам с подсветкой слов темы в предпросмотре (кисть `BrushThemeMark` в светлой и тёмной темах), а режим «Показ → Тема…» теперь действительно фильтрует по теме упоминания. Тесты ×13.

124. **Группа 3: систематизация текстов по темам** (item 53): `Core/Themes/ThemeSystematizer` оценивает каждый файл по всем словарям (встроенные + свои темы, например «Космология» из `user_themes.json`) — вхождения слов с морфологией считаются по контекстам готовой сессии, без пересканирования корпуса; главная тема файла — максимум вхождений (при ничьей выигрывает словарь, идущий раньше; файлы без вхождений — «Без темы»). Вкладка «Темы» на странице «Корпус»: слева темы с числом файлов, справа файлы выбранной темы с оценками всех тем, словами-маркерами главной темы и открытием файла. Тесты ×7.

125. **Группа 3: ревизия по тексту плана (items 8, 31, 52)**: «Каталог» получил полноценное отклонение кандидатов — кнопка «✕» прячет написание из находок, «↺» возвращает, флажок «Показывать отклонённые» показывает вердикты, всё живёт в `%APPDATA%\EntityAnalyzer\catalog_ignored.jsonl` (append-only, действует последний вердикт по ключу «сущность|написание», сбои не роняют приложение). «Поиск по фрагменту» учитывает синонимы: варианты имён одной сущности из каталога подмешиваются в морфологический уровень (флажок «Синонимы (каталог)»), так что запрос «Azathoth» находит «Азатот» и с выключенным fuzzy. У сборщика отрывков (item 52) закрыт вопрос границ окна: отрывком становится только упоминание, в чьём сохранённом контексте реально видно слово темы (тест). Тесты ×7.

126. **Автотесты не трогают реальный профиль**: каталог профиля теперь собирается в одной точке — `Core/Persistence/ProfilePaths.DirectoryPath` (переопределение `ENTITYANALYZER_DATA_DIR`), и на неё переведены все пользовательские хранилища (кодекс, история, вердикты, цитатник, заметки дневника, эпитеты, глоссарий, темы, статистика, демо-корпус, семантические словари). `ui_smoke.ps1` без переменной отказывается стартовать и отдельно отвергает путь реального профиля; `verify.ps1` прогоняет CLI и GUI-смоук на временном профиле и завершает прогон шагом «profile-untouched» — файлы реального `%APPDATA%\EntityAnalyzer` сверяются со снимком до старта. Тесты ×5.

127. **Подсказка ярлыка — по-настоящему Unicode**: `create_shortcut.ps1` пишет описание ярлыка через `IShellLinkW` (широкие строки) вместо ANSI-вызова `WScript.Shell`, из-за которого кириллица в подсказке превращалась в «?????». Скрипт пересоздаёт ярлык «Entity Analyzer» на рабочем столе и лечит описания остальных ярлыков на этот же exe; результат читается обратно тем же Unicode-интерфейсом.

128. **Группа 4: семейное древо и GEDCOM** (items 5/5.1): `Core/Genealogy` читает GEDCOM (INDI/FAM, имена и события, альтернативные `NAME`, `PEDI` и `QUAY`, `CONC`/`CONT`, даты с диапазонами, «до н. э.» и приблизительностью), автоматически превращает файл в читаемый текст — сводка, хронологический обзор и карточки персон; `GedcomNarrator` не теряет одиночные записи, альтернативные имена и типы родительских связей. `FamilyTreeBuilder` строит древо и из GEDCOM, и из связей кодекса «породил»/«родитель»/«усыновляет»/«опекун»/«крёстный»/«названый»/«партнёр»: DFS убирает обратные рёбра (циклы не вешают раскладку), Kahn раскладывает узлы по поколениям, компоненты связности идут подряд, супруги встают рядом. `FamilyTreeLayout` детерминированно размещает карточки, `FamilyTreeHtml` выгружает самодостаточную интерактивную страницу (панорамирование, масштаб, поиск, карточка персоны, читаемый текст, типы и уверенность связей, переключатель гипотез) без внешних библиотек. Страница «Мир» → «Древо»: переключатель «Кодекс мира / Файл GEDCOM», импорт `.ged`, канва с поколениями, родительскими и супружескими связями, выбор узла, поиск, выбор ветви (компонента связности) и защита канвы от тысяч узлов, экспорт HTML и Markdown/текста. Тесты ×27.

129. **Группа 4: режим «генеалогическое древо» во встроенном графе** (item 5.1): в «Кодексе» у вида «Граф» появился переключатель «Совместные упоминания ↔ Генеалогическое древо». Граф теперь занимает всю рабочую область, а справа показывает карточку выбранного узла. Второй режим рисует карточки и связи порождения/родительства по поколениям, с супружескими пунктирами, подписями типов связей, штрихами для приёмных/опекунских/крёстных связей и бейджами уверенности; клик по узлу заполняет карточку, кнопка «Открыть в редакторе» возвращает к обычному виду. Переключение не зависит от сессии анализа, а правки связей сразу пересобирают древо. Тесты древа входят в блок 128.

130. **Группа 4: автособираемая хронология Мифов** (item 6): `Core/Chronology/WorldChronology` вытаскивает из текстов последнего прогона годы (`1928`, `1931`), давность («250 лет назад», «двадцать лет назад», «сотни тысяч», «млн/млрд лет»), эры/эпохи и временные маркеры; нормализует запись, привязывает nearby-сущности, дедуплицирует и сортирует от древнего к новому, ограничивает шум (500 записей, не более 6 одного вида на файл). Вкладка «Хронология» на странице «Мир»: сборка по кнопке, фильтр по виду, поиск, цитата с источником, открытие файла, экспорт Markdown. Тесты ×16.

131. **Группа 4: география и карта** (item 19): `Core/Geography` находит места по 19 классам (город, деревня, порт, остров, гора, плато, пустыня, озеро, река, море, океан, лес, долина, пещера, храм, башня, страна, континент, планета) двумя проходами — «класс + имя» и «имя + класс», плюс точное совпадение с газеттиром; встроенная база `default_place_gazetteer.json` (~130 реальных и вымышленных мест с координатами) и словари классов расширяются пользовательскими JSON. Для каждого места собираются написания, число упоминаний, файлы и цитаты; `GeographyMapHtml` рисует карту Leaflet с фильтрами классов, цветами, попапами и кликабельными цитатами, а при недоступности CDN показывает офлайн-список мест; `NominatimGeocoder` по явному нажатию уточняет координаты (кэш в профиле, пауза 1,1 с). Вкладка «География»: сборка, фильтры класса/координат, поиск, карточка места, цитаты и экспорт карты в HTML. Тесты ×12.

132. **Группа 4: древо иерархии** (item 5): `Core/Hierarchy/HierarchyTree` строит дерево из типизированных связей кодекса (`служит`, `находится в`, `породил`, `родитель`, `владеет`), сам выбирает корни, обрывает циклы по посещённости, повторные карточки превращает в ссылки «уже показано выше» и ограничивает глубину. Вкладка «Иерархия» страницы «Мир»: выбор участвующих связей, TreeView с цветами категорий, поиск, карточка узла, экспорт Markdown и JSON. Тесты ×5.

133. **Группа 4: исследовательский слой древа** (items 5/5.1, по мотивам дизайн-концепции сложных генеалогий): уверенность связи стала первоклассной — `CardLink.Confidence` (достоверно/вероятно/гипотеза/противоречиво/не указана) редактируется при создании связи и приходит из GEDCOM `QUAY`; тип родства (`PEDI`, ID и русские подписи связей) отделяет биологическое родство от приёмного, опекунского, крёстного, названого и партнёрского. На канве тип показан штрихом и подписью, уверенность — бейджем; в панели выбранной персоны перечислены её связи со статусами. Режим «Фокус» строит эго-сеть на 1–4 шага, переключатель «Гипотезы» скрывает предполагаемые рёбра, не меняя данные, а `FamilyTreeAudit` показывает сирот, похожие имена, несколько наборов родителей, гипотезы и противоречия с переходом к персоне. Экспорт HTML сохраняет типы, уверенность, легенду и переключатель гипотез. Тесты ×8.
134. **Навигация по непроверенным файлам**: «Результаты» получили кнопку «Следующий файл →» и прогресс по всему корпусу. `Core/Analysis/ReviewNavigator` считает проверенные/непроверенные цитаты и файлы, циклически ищет следующий файл с работой, а `VerdictResolver` восстанавливает сохранённые вердикты сразу на всю сессию по ключу «SHA-256 + позиция + вариант». Хэши берутся из инкрементального индекса (`Dashboard.TryGetIndexedHash`), поэтому переход не перечитывает корпус; кэш хэшей очищается при новой сессии. Если в текущей выборке работы нет, фильтры сбрасываются и поиск продолжается по всему корпусу; режим проверки переключается на «Непроверенные».
135. **Протокол проверки (экспорт вердиктов)**: вместе с отчётами пишутся `review_report.md` (сводка: всего/проверено/подтверждено/ложные/спорно/осталось непроверенных, файлы с непроверенными цитатами + таблица решённых цитат) и `review_report.csv` (machine-readable, поля в кавычках RFC 4180, стабильные коды `confirmed/rejected/uncertain` — как в `verdicts.jsonl`). Протокол появляется только при наличии хотя бы одного вердикта: без разметки набор файлов экспорта не меняется вовсе, обычные отчёты остаются прежними байт-в-байт (покрыто тестом). Состояние проверки и имя протокола видны на странице «Экспорт» и обновляются сразу после вердикта, массового вердикта или отмены; сводка считается тем же `ReviewNavigator`. Headless-прогон включает протокол явным флагом `--review-report`: CLI применяет сохранённые вердикты по SHA-256 из инкрементального индекса (файлы вне индекса дочитываются), после чего обычный экспорт добавляет `review_report.*`. Тесты ×8.

## Для грантовых заявок (digital humanities)

R2-30 «Грантовая упаковка»: проект сознательно собран так, чтобы закрывать типовые критерии грантовых программ (NEH Digital Humanities, ELIAS, РФФИ/РНФ-подобные конкурсы) без дополнительной подготовки заявки.

| Критерий | Чем закрыт в проекте |
|---|---|
| Открытый код и воспроизводимость | Полностью открытый репозиторий; пакет воспроизводимости `.earepro` (R2-12) — манифест, журнал прогона и инвентаризация корпуса с SHA-256; хеш-цепочка журнала (R1-21) — тампер-евидентная история |
| Проверяемость результатов | Независимая верификация рецензентом: научное резюме из пакета (R1-28) перепроверяет цепочку целостности без доступа к данным автора; самопроверка релиза при старте (R2-16) сверяет движок с встроенным эталоном |
| Методологическая прозрачность | Воронка фильтров raw→final с полными счётчиками в каждом отчёте; performance-gate против baseline.json (R1-14) фиксирует неизменность производительности |
| Образовательное применение | Демо-корпус «за 30 секунд» (R2-18), режим презентации, headless API (R1-12) для учебных сценариев и интеграции с LMS |
| Устойчивость инфраструктуры | Одна команда верификации `verify.ps1 -WithGuiSmoke`: сборка → 882 теста → публикация → CLI (с проверкой расположения кэша) → производительность → GUI-смоук (включая палитру) |

**Цитирование:** при публикации исследований, выполненных с помощью Entity Analyzer, прикладывайте `academic_summary.md` из пакета воспроизводимости — он содержит методологию, параметры прогона и контрольные суммы.
