# UX-обзор интерфейса Entity Analyzer (item 17)

Дата: октябрь 2026 · Область: `dotnet/src/EntityAnalyzer.App` (WPF, русскоязычный интерфейс)
Метод: эвристическая оценка (10 эвристик Нильсена), проход по основным сценариям,
разбор first-run опыта и клавиатурных сценариев. Наблюдения сверены с кодом
(`Views/*.xaml`, `ViewModels/*`).

---

## 1. Резюме

Интерфейс сознательно выдержан в «книжном» стиле: текст, волосяные линии,
точки-маркеры, никаких карточек и теней. Это редкая в инструментах DH (digital
humanities) аккуратность, и она решает главную задачу — исследователь читает
текст, а не борется с хромом интерфейса.

Слабые места до последней итерации лежали не в стиле, а в **обратной связи**:

- кнопки блокировались без объяснения причины («Найти» без прогона);
- критические функции не имели системного отражения (звёздочка цитатника не
  показывала состояние — привязка была к методу, а не к свойству);
- раскладка одного экрана перекрывала сама себя (тепловая карта по полю фильтра);
- часть возможностей была «невидимой» (Ctrl+F в отчётах молча ничего не делал,
  граф рисовался в 600×480 «по умолчанию» до первой раскладки).

Все перечисленные проблемы исправлены в Группе 1 (см. §4). Остаточные зоны
риска — плотность настроек на «Обзоре», отсутствие глобального поиска и
клавиатурной навигации по вердиктам (см. §5–6).

**Оценка по экранам (5-балльная шкала, после правок):**

| Экран | Оценка | Главный риск |
|---|---|---|
| Обзор (запуск) | 4 | плотность левой колонки настроек |
| Обзор (вкладка «Поиск и паттерны») | 4 | жаргон «паттерны», перегружена секциями |
| Результаты | 4 | много кнопок на цитате, нет клавиатуры вердиктов |
| Кодекс (карточки) | 4 | «кодекс» как метафора неочевидна новичку |
| Кодекс (граф) | 3,5 | после правок читаем, но подписи всё ещё плотные при 50+ узлах |
| Схемы | 4 | редактирование без undo |
| Отчёты | 4,5 | встроенный HTML-просмотр (WebBrowser/IE) медленный |
| История | 4 | сравнение прогонов требует пояснения |
| Экспорт | 4,5 | — |
| Справка | 4,5 | материала много, нет поиска по справке |

## 2. Что работает хорошо (сохранить при рефакторингах)

1. **Единый визуальный язык** — 83 ссылки на палитру через `DynamicResource`,
   ни одной фиксированной заливки. Благодаря этому ночная тема (item 14) — это
   один словарь цветов, а не второй комплект стилей.
2. **Одноразовые контекстные подсказки** (item R2-19): полоса подсказки на
   «страницу-первое-посещение» объясняет функцию без модальных туров.
3. **Палитра команд (Ctrl+K)** как альтернативная навигация.
4. **Empty states** с мини-онбордингом на «Обзоре»: 3 шага + кнопка
   «Что такое кодекс».
5. **Режим презентации (F11)** и масштаб 0,8–1,6× — редкая для инструментов
   забота о выступлениях и слабовидящих.
6. **Книжная типографика** (антиква для контента, гротеск для UI, моно для
   данных) — визуально отличает «человеческий» текст от машинных строк.
7. **Журнал + статус-строка** в рейке: длинные операции не «молчат».

## 3. Сценарий первого запуска (после правок)

1. Открывается «Обзор». Слева — параметры, справа — статус с тремя шагами.
2. «Выберите папку с .txt» → «Запустите анализ» → «Цитаты появятся на
   странице “Результаты”». Путь линеен, лишних решений нет.
3. Есть ускоренный вход: «Демо-корпус: попробовать за 30 секунд» (в палитре
   Ctrl+K и на «Обзоре»).

Остаточная проблема: **новичок не понимает слов «кодекс» и «паттерны»**, пока
не откроет справку. Метафоры хороши после расшифровки, до неё — шум.

## 5. Оставшиеся проблемы (приоритеты)

### P1 — заметно снижают эффективность

1. **Плотность настроек на «Обзоре».** Левая колонка — длинный свиток из
   7–8 `Expander` (профиль, параметры парсинга, фильтры, regex, форматы,
   сущности, доп. папки, кэш, оформление). Опытный пользователь знает, где
   что, новичок прокручивает всё.
   *Рекомендация:* сгруппировать в 2 секции — «Запуск» (профиль, корпус,
   сущности) и «Тонкая настройка» (всё остальное, свёрнуто по умолчанию).

2. **Нет глобального поиска.** Ctrl+K палитра содержит только фиксированный
   список команд, при этом в приложении три разных поиска: фильтр на
   «Результатах», фильтр дерева отчётов, фильтр карточек кодекса.
   *Рекомендация:* в палитре — живой поиск по карточкам кодекса, отчётам и
   найденным цитатам с переходом Enter'ом.

3. **Вердикты «✓ / ✗ / ?» — только мышью.** Три кнопки на каждой цитате,
   клавиатурной альтернативы нет (Ctrl+S решает только цитатник).
   *Рекомендация:* клавиши `Y`/`N`/`U` (или 1/2/3) для выбранной цитаты +
   видимая подсказка в легенде.

4. **Терминология.** «Кодекс», «ветвь», «цитатник», «паттерны» — точные
   метафоры, но требуют глоссария. Способ уже есть (кнопка на «Обзоре»),
   он не виден в момент первого контакта.
   *Рекомендация:* inline-расшифровка в empty state и тушках кнопок;
   в справке — глоссарий одним блоком.

5. **Масштаб интерфейса** — подпись «Ctrl + колесо» есть, но нет числового
   значения и быстрых кнопок «−/+» (например, для скриншотов в грант).
   *Рекомендация:* добавить в «ОФОРМЛЕНИЕ» слайдер/счётчик масштаба.

6. **Встроенный просмотр HTML-отчётов** использует `WebBrowser` (движок IE):
   медленный, небезопасный, капризный.
   *Рекомендация:* давно есть запасной «Открыть в браузере»; сделать его
   основным, встроенный просмотр — сворачивать за кнопку «Показать здесь».

### P2 — полировка

7. **Управление вердиктами и цитатником необратимо** (нет undo). Список
   вердиктов пишется в `verdicts.jsonl`, отменить можно только вручную.
8. **Ctrl+S контекстный** (карточка / паттерн / звёздочка) — это нормально,
   но подсказка о текущем значении должна быть видна на самой странице.
9. **История:** сравнение прогонов требует пояснения, что именно
   сравнивается (метрики, а не тексты).
10. **Справка без поиска** — при 7 разделах поиск по тексту был бы полезен.
11. **Фокус-рамки:** `FocusVisualStyle={x:Null}` у большинства стилей — при
    навигации с клавиатуры точка фокуса не видна. Для Tab-навигации стоит
    вернуть тонкую рамку фокуса (1 px `BrushBorderLight`).

## 6. Доступность (a11y) — текущее состояние

| Критерий | Состояние | Замечание |
|---|---|---|
| Контраст (светлая) | Хорошо | текстовые пары ≥ 7:1 на фоне #F9F9F7 |
| Контраст (тёмная) | Удовлетворительно | проверять при правках палитры; правила — в шапке `Dark.xaml` |
| Масштаб | 0,8–1,6× | сохраняется между сеансами |
| Клавиатура | Частично | нет видимого фокуса, нет горячих клавиш вердиктов |
| Язык | Русский | зафиксировано продуктовым решением (R2-10) |
| Скринридер | Не проверялся | автоматизация имён кнопок неполная (у части иконок только текст) |

## 7. Метрики для проверки улучшений

1. Время «первый запуск → первая цитата» (цель: ≤ 3 минут с демо-корпусом).
2. Число шагов до первого экспорта (цель: ≤ 5).
3. Доля цитат, помеченных вердиктом, за первый сеанс (растёт при клавиатуре).
4. Количество кликов/нажатий на одну проверенную цитату (цель: ≤ 2).
5. Возвраты к справке после первого дня (падает при inline-расшифровках).

## 8. Рекомендуемый порядок работ (следующая итерация)

1. Группировка настроек «Обзора» (P1-1) — чистый рефакторинг XAML.
2. Поиск в палитре по карточкам (P1-2) — данные уже есть в `CodexViewModel`.
3. Горячие клавиши вердиктов + легенда (P1-3).
4. Глоссарий: 8 терминов в справке + inline-подсказки (P1-4).
5. Слайдер масштаба (P1-5) и фокус-рамки (P2-11).
6. HTML-отчёты по умолчанию — во внешний браузер (P1-6).

Пункты 1–3 закрывают самые частые затруднения, не затрагивая ядро анализа.
Все сценарии Группы 1 (item 39–51) проверены повторно на текущей сборке;
остаточные рекомендации не блокируют выпуск.
