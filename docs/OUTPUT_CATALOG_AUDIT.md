## 9. Каталог vs генерация вариантов

Это блокер для любого catalog-only фикса.

### 9.1. Код-путь

1. `CodexSearchAdapter.ToDefinitions` (`Codex/CodexSearchAdapter.cs`) складывает
   в `Irregular` алиасы, canonical и имя карточки. Для `Книга Эйбона` в
   `Irregular` попадают, среди прочего, `Книгу`, `Книга Эйбона` и
   `Book of Eibon`.
2. `EntityCatalog` (`Variants/EntityCatalog.cs`, конструктор) сначала делает
   `Absorb(def.Irregular)`, затем при `generateVariants`:
   - `factory.GenerateTwoPass(def.Canon, def.Irregular, isCommon)`;
   - если `def.Name != def.Canon`, `factory.GenerateTwoPass(def.Name, [], isCommon)`.
   Для карточки с canonical `Book of Eibon` и name `Книга Эйбона` второй
   вызов обязателен.
3. `VariantFactory.Generate` (`Variants/VariantFactory.cs`) вызывает
   `RussianMorphology.DeclineCompound(canon)` для любого канона с пробелом.
4. `RussianMorphology.DeclineCompound` (`Variants/RussianMorphology.cs`) в
   текущей реализации склоняет **каждое слово отдельно** и возвращает
   bare-формы: `Книга` → `Книге`, `Книгу`, `Книгах`, ...; `Эйбона` →
   `Эйбоне`, ....

`CodexService` в этом пути нет; `HomonymClassifier` тоже не участвует — он
не вызывается из `EntityCatalog`/`AnalysisEngine`, это тесты/утилита. Это не
OCR и не source-порча.

### 9.2. Runtime-проверка

Проверка на собранной `EntityAnalyzer.Core.dll` (временный console, не
изменение репозитория):

```text
EntityCatalog with empty irregular:
  Книгу: True
  Книге: True
  Книгах: True
  Книгой: True
  Книгами: True
  Книга: False
  Эйбоне: True
```

`EntityCatalog` с `Irregular=[Книгу]` даёт тот же набор. `Книга` не
появляется, потому что `Decline` не возвращает исходную nominative-форму.

### 9.3. Что это значит

- `Книгу` **есть** в каталоге (49 алиасов карточки), поэтому утверждение
  «его нет в каталоге» неверно. Но вывод, что удаление одного алиаса не
  исправит вывод, верен: форма генерируется из `Name`.
- `Книге`/`Книгах`/`Книгой`/`Книгами` — generated-only, 3 682 строки;
  `Книгу` — alias + generated, 2 586 строк; все пять — generic bare-формы.
- Поэтому catalog correction для этой карточки должен включать **две**
  части: (а) убрать generic alias `Книгу` (и решить судьбу `Latin`/
  `Atlantean` и т.п.), (б) изменить generation policy, чтобы composite name
  не давал standalone head-noun forms. Одно без другого не работает.
- Возможные направления policy (не реализованы): склонять полную фразу
  (`Книге Эйбона`), не эмитить части составного имени как отдельные
  варианты для generic-head names, либо требовать qualifier/marker на
  match-time. Выбор — отдельное решение после probe 2; production сейчас не
  меняется.
- Для `Наг и Йеб` та же `DeclineCompound` даёт `Нага`/`Нагов`/...; для
  `Плато Ленг` — `Ленга`/`Ленгом`, что нормально. Значит policy не может
  быть «отключить `DeclineCompound` глобально»: нужно различать generic
  head и собственное имя.

Граница: **catalog alias-only fix не является достаточным**; **generator fix
не является catalog mutation**; их нельзя смешивать в одну операцию.

## 10. Catalog correction: таксономия (не cleanup, не мутация)

Ничего ниже не выполнено. Это четыре разные операции; смешивать их нельзя.

### 10.1. Четыре операции

| Операция | Что делаем | Что не делаем | Пример |
|---|---|---|---|
| `owner_reassign` | Убираем дубль с неверного владельца; правильная карточка уже содержит форму. | Не создаём новую карточку и не «улучшаем» владельца на глаз. | `Cxaxukluth` |
| `misattribution_removal` | Убираем форму из карточки, потому что это отдельная сущность/титул без подтверждённого владельца. | Не переназначаем на другую карточку без карточки/источника. | `Zhar` |
| `homonym_removal` | Убираем омоним. | Не добавляем новую карточку в этом проходе. | `Лао` |
| `no_op` | Оставляем как есть; проблема в источнике/контексте. | Не удаляем из-за OCR. | `Leng` |

epithets, по которым нет единственного владельца. До решения они

## 11. Что это меняет в probe-интерпретации

- Top-4 concentration (>70%) действительно требовала аудита каталога; она его
  получила.
- Но **25/25 top-4 misleading не бывают только каталожными**: 12/25 — source
  degradation, 13/25 — catalog (9 generic/title, 4 owner/homonym).
- `strong`-страта не может быть спасена одним match-time фильтром: 3 из 5
  misleading-strong — source (`Zhar`, `Leng`, `Nug`), 2 — catalog
  (`Лао`, `Гисгут`).
- `Leng` не удалять. `Zhar`/`Lloigor`/`Cxaxukluth` — не «OCR-шум», а
  owner/catalog defects; source лишь усиливает их частоту.
- 302-файловый OCR-список — очередь, не source exclusion; file-level
  детектор подстановок выделяет ровно 35 файлов, а не 302. См.
  [`OUTPUT_SOURCE_AUDIT.md`](OUTPUT_SOURCE_AUDIT.md). Source batch 35 — это

## 12. Ограничения
